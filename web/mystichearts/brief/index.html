At a glance

Three audiences, one surface.

Mystic Hearts is the product surface; HAND Protocol provides the accompaniment underneath. Every screen serves one of three roles, and almost every interaction either earns, spends, or records a credit.

Member

Browse, attend, give back.

The public face of Mystic Hearts. Members find practitioners, RSVP to events, log attendance, review what they experienced, claim bounties, and redeem credits for sessions.

  • Browses without an account; signs up to act.
  • Earns credits through bounty completion or admin‑logged hours.
  • Spends credits 1:1 on sessions, partial on event discounts.
Practitioner

Invite‑only, curated.

Admin‑invited healers who post events and offer 1:1 sessions through a real‑time booking calendar. They control their feedback window and verify attendance via QR, link, or spoken code.

  • No public application; admin issues invites.
  • Generates attendance code + QR + shareable link per event.
  • Reads anonymous reviews; cannot de‑anonymize.
Admin

HAND ops + curator, fused.

One role in v1, splittable later. Runs the bounty board, verifies completions, issues credits, invites practitioners, vets specialists, and tends the modality taxonomy.

  • Posts bounties at two tiers: general 1:1 and specialist.
  • Manually logs Tier‑1 hours when work bypasses the board.
  • Owns the modality list, fed by the Mystic Hearts collective.

Data model sketch

The shape of what we store.

Not a schema yet, just the entities that have to exist for v1 to cohere. Every cross‑Reciprocate concept hangs off group_id, which is what dark‑launches the multi‑group future without a migration.

U User

  • id uuid
  • email · name
  • role: member | practitioner | admin
  • is_specialist · specialist_areas[]

G ReciprocateGroup

  • id · slug · name
  • Mystic Hearts is row 1

P PractitionerProfile

  • user_id · group_id
  • bio · photo_url · location
  • modality_ids[] · session_duration
  • pricing_model · accepting_bookings

M Modality

  • id · name
  • group_id
  • list TBD from MH

E Event

  • id · host_user_id · group_id
  • type: practitioner_hosted | group_gathering
  • starts_at · ends_at · capacity · location
  • price_model · attendance_code · qr_url

R EventRSVP

  • event_id · user_id
  • status: rsvp'd | attended | no_show

A EventAttendance

  • event_id · user_id
  • verified_at · method: qr | link | code
  • unlocks review eligibility

V Review

  • id · event_id · practitioner_user_id
  • member_user_id · rating · body
  • is_visible · submitted_at
  • anon enforced at RLS

C PractitionerAvailability

  • practitioner_user_id
  • recurring_rule (RRULE) | one_off_slot
  • duration_min · timezone

B Booking

  • id · practitioner_user_id · member_user_id
  • starts_at · ends_at
  • status · payment_method
  • credit_amount · cash_amount

$ Bounty

  • id · group_id
  • tier: general | specialist
  • credit_value · expires_at
  • status: open | claimed | submitted | completed

K BountyClaim

  • bounty_id · user_id
  • claimed_at · submitted_at
  • submission_evidence
  • verified_by_admin_id

¢ CreditTransaction

  • id · user_id · group_id
  • amount (signed)
  • source_type · source_id
  • this table IS the ledger

I PractitionerInvite

  • id · email · token
  • invited_by_admin_id
  • status: sent | accepted | expired
Build phasing

What ships when.

Phase 1 alone is the deep end of the 3‑to‑6‑month range. If the launch date tightens, Phase 1.5 items demote into Phase 2 before architecture starts.

Phase 1

Ship‑blocking v1

Launch 2026
  • Next.js + dedicated Supabase
  • Auth with 3 roles
  • Public practitioner directory
  • Public event feed
  • Practitioner invite + onboarding
  • Real‑time booking calendar
  • QR / link / code attendance
  • Verified anonymous reviews
  • Bounty board (general tier)
  • Credit ledger (public + private)
  • Redemption: full credits → sessions
Phase 1.5

Aim for launch · drop without blocking

Same window
  • Partial credits → event discounts
  • Specialist designation on profiles
  • Specialist‑tier bounties
  • Admin manual hour logging
  • Email notifications via Resend
Phase 2

Post‑launch, on the roadmap

Months 7‑12
  • Specialist vetting workflow
  • Specialist rate table
  • Stripe for cash events
  • Calendar exports (iCal · Google)
  • SMS notifications
  • Cancellation policy in code
  • Review flagging + moderation
Phase 3+

Parked

When the time comes
  • Cross‑Reciprocate activation (group #2)
  • 3D / drone / experiential surfaces
  • Mobile app
  • Own domain migration
  • Sovereign Reciprocate AI workstream
