Level up & graduate

⏱ About 40 minutes 🎓 Ends with a diploma-shaped feeling

You've built and shipped. This last module hands you three upgrades that working developers rely on daily — each one, with Claude doing the heavy lifting, takes minutes to adopt — and then talks honestly about what's next.

Upgrade 1 · Save points (git)

Ever wished you could snapshot your project when it works, so you could experiment fearlessly and rewind if needed? That exists — it's called git, and it's the save-point system every developer on Earth uses. The reputation is "hard"; the reality with Claude is one prompt:

Copy into Claude Code — in your project folder 
Set up git in this project and make a first commit called "version 1 - live on the internet". Then explain in two sentences what you just did. From now on, whenever I say "save a checkpoint", commit the current state with a short description of what changed.

From then on your workflow grows exactly one phrase: after anything you like, say "save a checkpoint." If an experiment goes sideways: "take us back to the last checkpoint." You never have to learn git commands — you just have to remember save points exist.

Upgrade 2 · Project memory (CLAUDE.md)

Remember how each new session starts fresh? There's an exception: a file called CLAUDE.md in your project folder, which Claude reads automatically at the start of every session. It's the place for standing instructions — your project's house rules. Type this in your project:

Copy into Claude Code 
/init

Claude studies your project and writes a starter CLAUDE.md. Then personalize it — the payoff is huge for beginners. Ask Claude to add lines like:

  • "I'm a beginner — explain changes in plain language as you make them."
  • "Keep this project simple HTML/CSS/JS. No frameworks."
  • "The look should stay warm and friendly — cream background, rounded corners."

Every future session now starts with Claude already knowing your rules — continuity without re-explaining. Update it whenever you catch yourself repeating an instruction.

Upgrade 3 · The habit stack, on one card

Everything this course tried to install, in review order:

  • Describe outcomes, specifically. Where, what, how it should end up.
  • One change at a time. Describe → build → look → repeat.
  • Look at everything. Trust, then verify. "Done!" means "check me."
  • New task, new session. /clear is a reset button, not a loss.
  • Plan mode before big changes. Proposals are free.
  • Bug reports in three lines. Did / expected / instead — plus screenshots.
  • Save checkpoints. Experiment fearlessly, rewind freely.
  • Ask "explain that" relentlessly. It's how the work becomes yours.
  • Stuck quietly is the only mistake. Humans are a button away.

Where to go from here

Three directions, all good, all compatible:

  • Keep building your thing. Your NOTES.md wishlist, a second page, a custom domain, that feature you weren't "allowed" to build in the course (a form! a map!). Ask Claude — with plan mode — how it would add it.
  • Build for your people. Someone in your life runs something that deserves a decent website, and you now make those. Repeat Modules 05–07 with their project; it'll take a third of the time.
  • Build with HAND. HAND Protocol exists to put skills like your new one to work for communities that need them — real projects, real people, hands helping hands. Reply to your welcome email or tell your guide you want in, and we'll find where your hands fit.
You didn't just learn a tool. You changed what "I'm not technical" means when you say it — you can't quite say it anymore.
