HAND Learn / Module 03 of 08

Your first conversation

⏱ About 45 minutes 🛠 Hands on keyboard — you'll make a real web page

Open the Claude app, go to the Code tab, and select your claude-practice folder from Module 02. Today you build your first page, watch the permission system in action, and — on purpose — tell Claude "no."

Job one: make a page

Copy this in exactly as it is (there's a copy button):

Copy into Claude Code 
Create a file called hello.html — a simple, cheerful web page that says "I made this with my own hands (and Claude's)". Give it a soft cream background, one big friendly headline, and today's date. Keep everything in this one file.

Now watch what happens, because this is the core rhythm of everything:

  1. Claude thinks for a moment and announces what it's going to do.
  2. It pauses and asks permission to create the file, showing you the content it wants to write. This is the permission prompt from Module 01, live.
  3. Read it — you'll be surprised how much of it makes sense. Then press Accept.
  4. Claude confirms, and hello.html now exists in your folder. Not in a chat window. On your computer.

Look at your creation: open the claude-practice folder on your Desktop and double-click hello.html — it opens in your web browser. That's a real web page and you just shipped it to an audience of one. It counts.

Job two: change it

Nobody gets things perfect the first time — with Claude Code, you're never supposed to. Building happens in small rounds of describe → build → look → adjust. Try one:

Copy into Claude Code 
Nice! Now make the headline much bigger, add my name under it (my name is ____), and put a warm orange line under the headline.

(Fill in your name before you send it.) This time Claude edits the existing file, and the permission prompt shows a diff: red lines are what's being removed, green lines are what's being added. You don't need to understand every symbol — the shape of it tells the story.

Accept, then refresh the page in your browser (the circular arrow, or Ctrl+R / Cmd+R). Your change is live. This edit-accept-refresh loop is exactly how you'll build your real app.

Job three: say no (on purpose)

The Accept button gets all the attention, but the Reject button is where your power lives. Let's use it deliberately, so the first time is calm and not mid-crisis:

Copy into Claude Code 
Change the page's background to bright neon green.

When the permission prompt appears — press Reject. Notice two things: your file is completely untouched (refresh the browser and check), and Claude doesn't sulk. It asks how you'd like to proceed instead. Tell it:

Copy into Claude Code 
Let's keep the cream background. Sorry, I was testing the reject button — you passed.
Remember this feeling

Nothing happened until you allowed it. You can reject any change, stop any task (the square stop button), and nothing breaks. Claude Code moves fast, but you hold the keys.

Job four: make it teach you

Claude Code isn't just labor — it's the most patient tutor you'll ever have. After any change, you're allowed to ask what just happened:

Copy into Claude Code 
Open hello.html and walk me through it like I've never seen code: what are the main parts of this file, and what does each one do? Keep it short and friendly.

You never need to feel dumb asking. It has no eyebrows to raise. The learners who grow fastest are the ones who ask "explain that" constantly — make it a reflex.

What just happened, zoomed out

In one sitting you used every fundamental motion of Claude Code:

  • Described an outcome in plain English → Claude created a file.
  • Reviewed a diff and accepted an edit.
  • Rejected a change and redirected — staying in charge.
  • Asked for an explanation — turning work into learning.

Everything from here on — the whole app you'll build — is these four motions, repeated with more interesting material.

Checkpoint

Did the reps

In a diff, what do the green and red lines mean?

A diff is a before/after: red = taken out, green = put in. Reading the shape of diffs gets comfortable fast.
