# WaterDrop Code Review

Sunlit legibility and offline-capture integrity are the weak spots: 2 P0 (illegible flagship readout, broken modal contract), 9 P1 (data-loss/verdict-discard/CSV-injection plus desktop layout + a11y wiring), 8 P2 polish.

## P0

- **src/features/conditions/GaugeDetail.tsx:134-138** — The flagship Discharge readout (the single "is it runnable" number PRODUCT.md L45 requires at AAA/7:1) is tinted with raw mid-luminance `VERDICT_COLORS` on limestone: good 3.24:1, low 2.52:1, high 3.51:1 — failing even AA 4.5:1 and effectively illegible in glare. Fix: render the value in `--text-strong` (16:1) and carry verdict color only via the StatusPill above it; if a hue tint is wanted, use the darker pill-text variants and add a `readout` color set that clears 7:1.
- **src/features/crew/ComposePanel.tsx:302-308** — The compose overlay declares `role="dialog" aria-modal="true"` and covers the app, but implements no modal contract: no Escape-to-close, no focus trap, no return-focus; keyboard/SR users Tab out into the map behind and can't dismiss it (PRODUCT.md L48 full keyboard path). Fix: port CrewGate's pattern — capture `activeElement` on open, focus the heading/first control, add a keydown listener that calls `cancelCompose()` on Escape and wraps Tab/Shift+Tab, and restore focus on close.

## P1

- **src/features/conditions/usgs.ts:134-145** — `staleReading()` preserves last-known `dischargeCfs` but hard-codes `verdict:'unknown'`, which `corridor.ts` ranks lowest, so a full USGS outage flips the whole-corridor pill from "Runnable" to "No data" while a perfectly good last-known flow is still shown — discarding "the answer," the product's whole point (PRODUCT.md L50, "never a dead screen"). GaugeDetail then shows "Live gauge data unavailable" directly above a real discharge value. Fix: when `prev.dischargeCfs != null`, recompute/carry the verdict forward (keep `stale:true`) so the pill reads "Runnable (offline, last known 2h ago)".
- **src/features/crew/exportObservations.ts:4-11** — CSV formula injection: `csvField()` RFC-4180-quotes but never neutralizes free-text fields starting with `= + - @`; a note like `=HYPERLINK(...)` from ComposePanel executes when the trusted field log is opened in Excel/Sheets. Fix: if the stringified value starts with `=+-@\t\r`, prefix a `'` and force-quote, before the existing escape.
- **src/features/crew/ComposePanel.tsx:284-295** — On the offline-critical capture path a failed `saveObservation` is swallowed with only `console.error`; the Save button just stops spinning, so the steward can close believing it saved and silently lose field data — the exact "capture must never lose data" failure (PRODUCT.md L39). Fix: add a `saveError` state, render an inline footer error ("Could not save — your entry is kept, tap to retry") with Save re-enabled and the draft intact.
- **src/features/crew/ObservationDetail.tsx:66-71** — Object URLs are created and revoked inside `useMemo` during render, keyed on the whole `obs` object; any save/delete re-runs `loadObservationsIntoStore()` giving `obs` a new identity, so the memo synchronously revokes the blob: URLs the committed `<img>` tags still point at (thumbnails blank; side effects in render break under StrictMode). Fix: move create/revoke into a `useEffect` keyed on `obs?.id` + photo ids, revoke the previous batch in cleanup; never revoke in render.
- **src/features/conditions/CorridorConditionsPill.tsx:34-83** — No `aria-live` anywhere (grep: zero matches); the pill's `aria-label` is recomputed on every 5-min/focus refresh but a changed label on a static button is never announced, so a blind planner gets no notice when the verdict flips good→high or data goes stale. Fix: add a visually-hidden `aria-live="polite"` region that emits a sentence ("River conditions updated: High water. 920 CFS." / "Showing last known reading, gauge offline.") only on actual change.
- **src/components/ui/Field.tsx:19-44** — Field builds `describedById` and puts it on the `<p>` but never wires `aria-describedby` to the control, and doesn't expose it; CrewGate's passcode input has `aria-invalid` but no description, so "That passcode did not match" isn't programmatically associated (WCAG 1.3.1/3.3.1). Fix: clone the child (or expose the id) so the control gets `aria-describedby={describedById}`; at minimum thread it to CrewGate and the ComposePanel contamination/species fields.
- **src/components/ui/StatReadout.css:25-30** — Readout units (CFS, ft, °C) use `--text-muted`/`--stone-500`, which is ~4.5:1 on the lifted surface (fails the AAA 7:1 bar PRODUCT.md sets for primary readouts) and ~4.3:1 on the `--stone-50` canvas (below AA). Fix: use `--stone-600`/`--stone-700` (≈7:1 on surface) for units and any text that is part of a primary readout; keep `--stone-500` for secondary chrome on the lifted surface only.
- **src/components/ui/Sheet.css:14-16 (+ ComposePanel.css:1-9, AppBar.css:14-23)** — The app has zero width breakpoints: the 560px bottom sheet, the full-bleed compose overlay, and the 560px-clamped app-bar island all strand mobile compositions on a 1440px desktop (sheet floats over empty map; compose inputs stretch ~1360px past a readable measure; app-bar content bunches center with two-thirds empty). The bottom sheet is the deliberate mobile surface, but desktop/planning use (PRODUCT.md L48) needs a real layout. Fix: add a ≥768/900px breakpoint that re-composes the sheet into a docked side rail, constrains `.wd-crew-compose__scroll` to `max-width:560px; margin-inline:auto`, and balances the app bar (true left/right anchoring); re-anchor floating controls and drop the `--sheet-peek` vertical term in that layout.

## P2

- **src/features/map/markers.tsx:123-138** — Gauge (30×30) and observation (28×28) markers are tappable but below the 44px touch target PRODUCT.md/DESIGN.md require for wet/one-hand use; they're the smallest targets on the hero surface. Fix: pad the divIcon container to a ≥44px hit area with the visible badge centered, matching the 44px access pins.
- **src/features/crew/ComposePanel.tsx:320-330 (+ ComposePanel.css:317-320)** — The selected "moderate" severity segment puts white text on `--sev-moderate` (~3.5:1, fails AA) while trace/minor/severe pass. Fix: give "moderate" dark-ink text (or darken the hue) so the selected label clears 4.5:1; pick per-step text color by measured contrast.
- **src/features/conditions/TrendChart.tsx:23** — Axis tick labels use `#7c8a7e` on white (~3.6:1, fails AA for small numeric data) and the low/high threshold labels inherit the light verdict hues (low ~2.5:1). Fix: darken axis text to ~stone-600 (≈4.6:1) and render reference-line labels in the same darker neutral or the darkened pill hue.
- **src/components/ui/Sheet.tsx:185-224** — The Sheet always carries `role="dialog"` and sets `aria-modal=true` only at the full detent, but never traps or moves focus, so the modal promise is unkept (Tab still reaches the map) and the label isn't tied to the visible `<h2>`. The sheet is intentionally non-blocking, so fix by dropping `aria-modal` (treat as `role="region"`/complementary with `aria-label` bound to the heading) rather than implementing a trap.
- **src/features/crew/exportObservations.ts:82,109** — The CSV Blob lacks a UTF-8 BOM, so Excel on Windows mojibakes species names, accented notes, and µS/cm. Fix: prepend `﻿` to the CSV Blob (leave GeoJSON unchanged).
- **src/features/crew/ComposePanel.tsx:231,271** — Two unguarded `crypto.randomUUID()` calls on the photo-add and save paths throw outside secure contexts (plain HTTP, older webviews) — the never-lose-data path. Fix: a small `newId()` helper with a `Date.now()`+random fallback.
- **src/features/crew/CrewControls.tsx:67-92** — No teaching empty state for zero observations; a fresh crew device just shows "0 observations" with disabled exports, missing the design-system "No observations yet — pin your first sighting" cue (DESIGN.md L125). Fix: when crew mode is active and `observations.length === 0`, surface that teaching line in the crew menu or a one-time peek-sheet hint.
- **src/features/conditions/CorridorConditionsPill.tsx:38-44** — The initial-load skeleton is wrapped in `aria-hidden="true"` with no live region or label, so AT users get nothing in the app bar for the headline "can I float?" verdict during load. Fix: keep the Skeleton decorative but give the container a visually-hidden "Checking river conditions" label (drop `aria-hidden` from the container).
